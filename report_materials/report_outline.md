# PAI最終課題 技術レポート：章立てと記載内容

**仮題：単眼カメラの床境界検出に基づく危険度推定と、シミュレーション上のロボットの安全制御**

凡例：
- 数値はすべて実行ログからの値です。各所に根拠のファイルを示します（パスは `risk_system/logs/` 基準）。
- **「検討」**は、データから読み取れる範囲の考察案です。執筆時に判断してください。
- **【不足】**は、データがなく今は書けない項目です。
- 動画に映る数値はここに使っていません。

## 1. 研究背景

- 人と同じ空間で動くロボットには、周囲の危険を判断して速度を変える仕組みが必要になる。
- 単眼カメラは安価だが直接距離を測れないので、幾何的な仮定を用いて距離を推定する方法を検討する。
- 実機の前にシミュレーションで、センサーから制御までの一連の動きを検証する意義を述べる。
- **【不足】** 先行研究の調査はしていません。参考文献は執筆時に追加が必要です。

## 2. 目的

1. Gazebo上のロボットカメラの画像だけから、障害物と人の危険度を0〜100で計算する。
2. 危険度に基づき、減速・停止・回避・待機を自動で行う。
3. カメラや各ノードの異常時に、安全側に停止する。
4. 上記を実測ログで定量的に評価する。

## 3. システム構成

- 図：`system_architecture.md` の図1〜3。
- 環境：ROS 2 Humble、Ignition Gazebo 6.16、Docker（`reproducibility.md`）。
- ロボット：差動二輪＋摩擦0のキャスター2個、カメラ高さ0.67 m、水平画角1.05 rad。
- ワールド：オフィス風。廊下に障害物3個、横切る人（`scene_images/environment/`）。
- 開発で修正したモデルの問題（図：`scene_images/before_after/`）：
  - カメラ画像が一様な灰色（全画素218）。ロボットが約38°傾いていたため。
  - 車輪の関節軸の向きの誤り。

## 4. 危険度認識方法

根拠：`risk_core.py`。

1. **床境界の検出：** 画像の列ごとに下から走査し、色の不連続または床の色からの外れを探す（物体の色は使わない）。
2. **距離の推定：** 平坦な床を仮定し、`d = h / tan(θ + atan((v − cy)/f))`（h = 0.67 m、θ = 0.10 rad、f ≈ 550 px）。これは測距ではなく推定。カメラから約1.2 m以内は死角。
3. **物体化：** 距離の近い列をまとめ、幅、高さ、左右端の位置を求める。
4. **人の判定：** 高さ1.15〜2.1 m、縦長、独立して立つ、という形状ルール。学習済みモデルではない。
5. **危険度：** `100 × 接近度 × (0.3 + 0.7 × 進路係数) × (0.7 + 0.3 × 信頼度)`。接近度は、障害物が3.5 m（0）〜1.4 m（1）、人が4.5 m〜1.9 m。接近度と進路係数がともに1の時は100。
6. **判定状態と動作：**

| 状態 | 条件 | 動作 |
|---|---|---|
| CLEAR | 検出なし | 通常速度で前進 |
| OBSTACLE_FAR | リスク < 30 | 通常速度で前進 |
| APPROACHING | 30以上70未満など | リスクに応じて減速 |
| PERSON | 進路上で4.5 m未満、または3 m未満に人 | 徐行 |
| STOP | リスク ≥ 70（60未満で解除）、進路上または1.25 m未満 | 停止、迂回または待機 |
| INVALID | 画像の欠落、途絶、異常 | 停止 |

重みと閾値は調整で決めた値で、衝突確率と対応づけて較正したものではないと明記してください。

## 5. 実験方法

| 実験 | 内容 | 手順 | データ |
|---|---|---|---|
| A 検知精度 | ロボットを既知の距離に置き、推定距離を真値と比較 | `test_detection_sweep.py` | `office_detection_sweep.csv`、`plainworld_detection_sweep_newdetector.csv` |
| B 走行 | 低速の開環走行で、オドメトリと真値を比較 | `motion_test.py` | `motion_test3_*`、`office_motion_*` |
| C 速度の影響 | 0.30 m/sからの停止距離、検知の遅れ、ピッチ | `test_speed_metrics.py` | `slalom_speed_metrics.txt` |
| D 閉ループ | 障害物3個と横切る人。目標へ走行 | `run_slalom.sh` | `slalom_final5.csv` ほか |
| E 故障注入 | 走行中に検知、カメラ、制御を停止 | `test_faults.py` | `slalom_fault_tests.txt` |

評価指標：推定距離の誤差、最小クリアランス（真値。ロボット外接円半径0.33 mが基準）、ピッチ、走行時間、停止までの距離。

人の移動はシナリオ上の動きです（`set_pose`、0.4 m/s）。ロボットには指令を出しません。

## 7. 考察

- **検討：色を使わない検出の有効性。** 色の違う箱、ケース、段ボールに同じ方法が適用できた。ただし床が単色の環境でのみ確認している。
- **検討：照明の影響。** 斜めの光では影が物体の基点と誤認され、オフィスで約0.2 m短く推定された（開発時の観察。`office_detection_sweep` 修正前の値は開発記録のみ）。
- **検討：リスク70以上でも走行している点。** 採用ランでは、リスク70以上かつ速度指令が正の行が12.7%ある。迂回中は正面の判定ではなく、経由点までの線分のクリアランスで判断するため。設計上の判断として説明が必要。
- **検討：カメラの視野の限界。** try4の接触は、視野の外の障害物へ曲がったことが原因。記憶で対策したが、記憶していない物体には効かない。
- **検討：人のラベルの揺れ。** 採用ランでも t ≈ 35 s 以降、約1.85 mの物体が obstacle になった（`slalom_final5.csv`）。待機の条件で止まっていたが、最初から障害物と判定されると、人を迂回する可能性がある。
- **検討：人の誤判定。** try2で、ケースと奥の植物が人と判定された（`scene_images/limitations/`）。
- **検討：タイムアウトが実時間である点。** RTFが低いとシミュレーション内の移動量が小さく見える。RTF 1では最大約0.45 m＋制動と見積もれるが、測定していない。
- **検討：シミュレーションと実機の差。** 停止距離約0.01 mは理想的な駆動の値で、実機には当てはまらない。

## 8. 結論

- 単眼カメラの画像だけから危険度を計算し、速度指令につなげる閉ループ動作を、シミュレーションで実現した。
- 特定の配置で、0.30 m/s指令、最小クリアランス0.268 m、走行59.2 sで目標に到達した。
- 異常時の停止を3種類の故障で確認した。
- 今後の課題：別の配置での評価、人の判定の改善（学習済み検出器）、測距センサーとの統合、実機での検証、cmd_velブリッジ停止への対策。

## 足りないデータの一覧

| 不足している項目 | 影響 | 対応案 |
|---|---|---|
| 配置を変えた評価 | 汎化性能を主張できない | 無作為な配置で複数回実行 |
| 同一設定での反復（final5の設定は1回） | ばらつきや成功率を統計的に述べられない | 同じ設定で10回以上 |
| 比較対象（危険度制御なし、固定速度、他の認識手法） | 提案手法の優位性を主張できない | ベースラインの実験 |
| YOLOの定量評価 | 不採用の理由が記録に残っていない（1枚約2秒、検出なしは開発時のコンソール出力のみ） | 測定し直してログに保存 |
| 走行中の推定距離と真値の比較 | 距離精度は静止時しか言えない | 物体の真値との距離もログに追加 |
| 人の真値位置の時系列 | 人との距離の推移を示せない | ログに追加 |
| 基本ワールドの故障注入ログ | `logs/fault_tests.txt` は後の実行で上書きされ、数値が残っていない | 必要なら再測定 |
| 現在のコードでの基本・オフィスワールドの再走行 | 古い2本のランは修正前のコード | 再走行 |
| cmd_velブリッジ停止、RTF 1付近の試験 | 安全性の主張に制限がある | 追加試験 |
| 実機での検証 | 実世界の性能は不明 | 実機実験 |
| 参考文献 | 背景と考察の裏付け | 文献調査 |
